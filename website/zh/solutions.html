行业方案

企业问题是组织化的，答案也应该是。

没有哪个单独的 agent 能上线一个产品、通过一次临床审核、批准一笔贷款， 或者独自打理一整批客户项目。 这些蓝图展示专家 agent 团队如何在 AgentGuide 上组合、治理与观测。 它们把 v0.5 已交付的运行时底座与路线图中的任务、跨 Agent workflow、 Artifact、记忆和合规控制组合在一起，是目标架构，而非预制产品。

软件研发

一座由 Agent 组成的软件工厂。

目标流程从需求一直延伸到发布：规划 agent 定义工作，托管的编码 agent 实现它， 评审 agent 提出质疑 —— 没有人点头，任何东西都上不了线。

PRDplanner → 架构设计design → 后端编码acp · codex 前端编码acp · opencode → QAtests → 安全审查audit → 发布审批human

琥珀色 = 人工决策点 · 虚线 = 并行扇出

  • 编码 agent 受托管 Codex 与 OpenCode 以 ACP agent 运行 —— 进程池化、会话可续接、转录可回放、文件系统边界由你划定。
  • 组合边界 builtin supervisor 与 plan-execute 今天可以协调内联角色；把工作交给独立 ACP Codex/OpenCode agent 仍需要跨 Agent workflow。
  • 审批积木 builtin MCP 操作可以挂起等待交互式审批；ACP agent 发起的权限请求也能交给运营者，并在超时后 fail-closed。
  • 按环节看 token 可归因事件提供 prompt、completion、缓存与推理 token；金额成本与预算强制执行仍在路线图上。

生命科学

面向证据充分的临床审核蓝图。

受监管的审核工作正是 agent 系统最容易失败的地方：不是败在能力，而是败在证据。 AgentGuide 已交付的事件与 trace 底座可以捕获经网关路由的模型和工具活动； 合规级、不可篡改的审计账本仍在路线图上，而最终裁决权始终在人手里。

方案解析parse → 医学编码meddra → 源数据核查sdv → 统计审查analysis → 合规检查gxp → 签核human

琥珀色 = 人工决策点

  • 运行证据 四类用量事件与交互 span 记录路由、工具、模型、时延、结果，以及归属明确时的 agent 身份。
  • 有边界的 builtin 审核员 builtin 定义强制使用所选模型路由与声明的 MCP 工具；全平台能力策略属于后续控制面。
  • 人工签核积木 被门禁的 builtin MCP 操作与 ACP 权限请求在未回应时 fail-closed。
  • 数据不出门 自托管、单二进制；模型端点由你选择 —— 最敏感的材料可以走 Ollama 本地模型。

金融服务

可追踪风控决策的目标架构。

KYC、风险、反欺诈、合规各司其职；网关可以让联合决策更可解释。 当前 trace 覆盖经路由的交互；可回放的决策血缘与合规审计属于 workflow 和 Artifact 路线图。

KYCidentity → 风险评分models 欺诈筛查patterns → 合规检查policy → 人工审批human → 决策存档record

琥珀色 = 人工决策点 · 虚线 = 并行扇出

  • 双人复核积木 选定的工具操作可以要求交互式人工审批，并在超时后 fail-closed。
  • 运行归因 Agent 归属明确时，相关事件携带责任 agent；故障区分客户端、上游与内部三类。
  • 爆炸半径受控 递归深度限制掐断 agent 套 agent 的循环；按 agent 的并发上限与超时直接拒绝而非排队。
  • 按业务台发密钥 每个团队或应用一把虚拟密钥 —— 限定可访问路由、设置过期或禁用，并集中吊销访问。

专业服务

给一人公司配一个交付后台。

独立顾问、独立开发者和一人工作室的时间，大量耗在项目建档、会议跟进、 客户周报与问题回复上 —— 必要，却不产生收入。让一支角色 agent 团队接管这层运营工作， 而任何东西到达客户之前，都要先过你的最后一眼。

上下文检索knowledge → 进展分析pm → 客户周报writer 回复草稿writer → 质量审阅review → 审阅发送human

琥珀色 = 人工决策点 · 虚线 = 并行扇出

  • 一支角色团队，而非一批人头 内联的规划、检索、撰写、审阅角色今天可以组成 builtin supervisor 拓扑。Codex 今天可以作为托管 ACP agent 运行；让两种运行时加入同一条持久流程仍需要跨 Agent workflow。
  • 接你已有的工具 邮件、文档、日历、代码仓库可以作为 MCP 服务接入；builtin 角色在执行时只获得定义中声明的工具。
  • 默认只出草稿 任何内容发给客户之前都要经过交互式人工审批 —— 未回应就是不发送。
  • 知识越攒越厚 项目 FAQ、模板与历史周报沉淀成可复用的资产库 —— 在路线图上，经由工件总线与共享记忆实现。

蓝图之外

同样的模式，适配你的行业。

上面每个蓝图都是同一个目标形状：专家 agent、有边界的资源、关键决策上的人工门禁， 以及关联的运行证据。它可以向下适配一人公司，也能向上服务大型组织。 在路线图上，持久审计、工件血缘与能力组合会让这些流程变成声明式的 —— 说出你要的结果，平台替你组建团队。
